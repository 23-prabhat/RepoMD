Rules and safeguards

The invariants that protect quality and trust.

  1. Keys stay server-side. GitHub and provider credentials never ship to the browser or CLI.
  2. Repository access is read-only. RepoMD reads metadata, tree paths, and selected file contents; it does not change the repository.
  3. Analysis is bounded. File count, file size, excerpts, timeouts, and output arrays have explicit limits.
  4. The schema is stable. Both products consume the same six-section analysis result regardless of provider.
  5. Failures stay client-safe. User messages do not reveal provider names, model names, credentials, or raw upstream errors.
  6. Storage stays local or temporary. Web data uses tab-scoped storage; CLI output stays in the active repository.
  7. Generated paths require evidence. The analysis prompt prohibits inventing files absent from the supplied repository tree.
  8. Private access uses least privilege. Tokens should have repository-specific read access to contents and metadata.

30-second explanation

Use this when presenting to judges.

“RepoMD has two interfaces: a visual web product and a repository-native CLI. Both call one Next.js analysis API, which reads a bounded set of files from GitHub and produces a strict six-section architecture report. OpenCode Zen is the primary intelligence engine and Groq is the automatic fallback. Credentials stay on the server, there is no central database, and every result can be explored in the browser or saved as local CLI artifacts.”
